One computation, two ways to see it.

The Rust library runs in the terminal and, compiled to WebAssembly, in your browser. TypeScript reads its trace and draws the graph. The moving dots are a slow explanation of those values, not measured execution timing.

Before → after

The previous browser demo pooled three routes using two fixed queries, then trained a JavaScript decision layer. The browser now runs Rust self-attention: every token produces its own query, key and value. Those are three querying tokens in one head. There is no decision head or training in this slice.

1. What lib.rs makes available

The public attention module holds the reusable model and its trace. The example module supplies synthetic inputs and parameters. Numerical helpers stay private. The browser adapter is compiled only when requested.

These module declarations organize code; they do not execute inference.

2. Follow attention.rs

  1. Check the input and parameter values.
  2. Project each token through the same Wq, Wk and Wv matrices.
  3. For every query, compare against every key using a dot product.
  4. Divide scores by the square root of key width.
  5. Apply softmax to each row.
  6. Use each row to blend the value vectors.
  7. Return every intermediate value with the outputs.

&self borrows the head; forward inference leaves its weights unchanged. Result passes a failure back to the caller.

Try it: follow query 0, then query 1. Each has a different distribution even though they use identical projection matrices.

3. The small numerical operations

Projection: for each output coordinate, sum input coordinate × matching matrix weight.

Softmax: subtract the largest score, exponentiate, then divide by the total. The subtraction avoids overflow without changing the distribution.

Try it: set all four Wq cells to zero. Every attention weight becomes one third. All three outputs become the mean of the value vectors. This is a manual edit, not training.

4. Across the browser boundary

JavaScript typed arrays arrive as flat rows. The adapter checks their sizes and builds Rust arrays. The same AttentionHead::forward function runs. Its trace is exported as typed arrays.

The binding tool generates TypeScript declarations from this adapter. The frontend copies the returned arrays and frees the Rust trace object. It contains no second implementation of attention.

Why this approach?

This small local CPU model does not need a server to be shared visually. WebAssembly lets the model remain Rust while the browser owns interaction. A future GPU runtime or hosted API would be a separate deployment choice.

Official sources guided module privacy, borrowing, recoverable errors, strict TypeScript, narrowing and browser ES modules. Choosing this runtime and graph layout is our project decision.

What to understand before the next slice

Attention weights sum to one; output coordinates do not have to. Keys determine comparisons; values supply what gets mixed. There are no positions, causal mask, multi-head composition, residuals, normalization, feed-forward block, typed decision head, dataset or backpropagation yet.

The graph is evidence of a forward calculation, not learned competence. We will add real training and its gradients when the Rust model supports them.
